# Building: compile-time options

This page explains how to configure and compile the code, and lists everything that is fixed at compile time.
Runtime parameters (the input file) are described in [input_file.md](input_file.md).

## Background

The package is a C99 code for Monte Carlo simulations of lattice Yang–Mills theories with the Wilson action.
The U(1) and SU(N) gauge groups in any space-time dimension are supported.
The package is built with GNU Autotools (`configure` + `make`). Several physical and technical choices are compile-time macros:
the gauge group, the space-time dimension, the parallelization model (OpenMP on CPU or OpenACC on GPU),
the imaginary θ term and the multicanonical algorithm. A program compiled with one set of options cannot run a simulation
that needs another set: rebuild in a separate directory or with `make distclean` first.

## Quick start

```bash
autoreconf -fi    # only needed if configure is missing or configure.ac changed
./configure N_c=3 ST_dim=4 --enable-use-openmp Num_threads=16 CC=gcc CFLAGS="-O3"
make -j
```

Alternatively, edit and run `build.sh` (see below), which runs `autoreconf`, `configure` and `make`
with a consistent set of options.

The simulation and analysis programs, when launched without arguments, print their usage and the compile-time
configuration (`print_compilation_details` in [lib/gparam.c](../lib/gparam.c)) and write a template input file
`template_input.example` in the current directory; the utilities print less (see
[programs.md](programs.md)).

## Configuration variables

Passed as `VAR=value` on the `configure` command line ([configure.ac](../configure.ac)).

| Variable | Macro in `config.h` | Default | Meaning |
| --- | --- | --- | --- |
| `N_c` | `NCOLOR` | 2 | Gauge group: `1` = U(1), `2` = SU(2), `N ≥ 3` = SU(N) |
| `ST_dim` | `STDIM` | 4 | Space-time dimension (must be > 1) |
| `Num_threads` | `NTHREADS` | 1 | Number of OpenMP threads (only with `--enable-use-openmp`; forced to 1 otherwise) |
| `Num_devices` | `MAX_DEVICES` | 4 | Maximum number of GPUs per node used by one process (OpenACC). Also used on CPU to simulate the splitting of replicas among devices |
| `Num_levels` | `NLEVELS` | 1 | Number of levels of the multilevel algorithm (multilevel programs only) |
| `Link_block` | `LINK_BLOCK` | 32 | Sites per block of the AoSoA storage of the gauge links; power of 2 from 1 to 256 (1 = AoS). Not used by the code yet: see [Link block size](#link-block-size) |
| `OPENACC_CFLAGS` | – | `-acc=gpu` for nvc, `-fopenacc` otherwise | Compiler flags enabling OpenACC. With nvc configure appends `-acc=noautopar` (also to user flags, unless they already mention `autopar`) |
| `CC`, `CFLAGS`, `LIBS` | – | – | Usual Autoconf variables. If `CFLAGS`/`CPPFLAGS` are not set, configure leaves them empty (no `-O2 -g`) |

Notes:
- The OpenMP thread count is fixed at compile time: the parallel loops use the clause `num_threads(NTHREADS)`.
- The vector lengths of the OpenACC kernels are macros of [include/accel.h](../include/accel.h) (`ACC_VL_UPD`,
  `ACC_VL_FLOW`, `ACC_VL_MEAS`), which can be overridden with `-D` in `OPENACC_CFLAGS`; see [architecture_and_portability.md](architecture_and_portability.md).
- The gauge group selection is done in [include/gauge_group.h](../include/gauge_group.h): every group operation
  `func` maps to `func_U1`, `func_Su2` or `func_SuN` ([include/u1.h](../include/u1.h),
  [include/su2.h](../include/su2.h), [include/sun.h](../include/sun.h) and the corresponding `*_upd.h`).

### Link block size

`Link_block` (B) is the number of consecutive sites of the even/odd ordering that will share a memory block in the
AoSoA storage of the gauge links; inside a block the site index runs fastest. B = 1 is the plain array of structures
(one site after the other).

- **Default:** 32 (best on average on A100 GPUs and on Sapphire Rapids CPUs in the benchmarks of
  [link_layout.md](link_layout.md)).
- **How to change it:** `./configure Link_block=16 ...`, or `LINK_BLOCK=16` at the top of `build.sh`.
  The value ends up in `config.h` as `LINK_BLOCK`.
- **Valid values:** powers of 2 from 1 to 256 (so that the division and remainder by B in the index arithmetic are
  shifts and masks): configure stops with an error otherwise, and
  [include/macro.h](../include/macro.h) checks it again at compile time (and defines it as 32 if `config.h` was
  generated by an older `configure.ac`).
- **Choosing B:** guidelines (GPU: at least one full 128-byte cache line per link element and block, i.e. B ≥ 8 for
  U(1) and SU(N ≥ 3), B ≥ 16 for SU(2); CPU: larger blocks were faster up to B = 32) and padding (if V/2 is not a
  multiple of B the even half is padded with fewer than B unused sites) are explained in
  [link_layout.md](link_layout.md).
- **Exception: CPU builds of 2D SU(N ≥ 5).** Without OpenACC, with `ST_dim=2` and `N_c ≥ 5`, use `Link_block=1`: in
  the benchmarks every block size B > 1 was slower than the plain AoS for 2D SU(5) on the CPU (B = 32 3–14 %
  slower), while every other group, dimension and GPU build gains with B = 32
  ([link_layout.md](link_layout.md#71-results-of-the-edge-cases)). SU(4) and 3D were not measured.
- **Status:** the parameter is defined, but the code does not use it yet: the links are still stored one site after
  the other.

## Enable options

| Option | Macro | Effect |
| --- | --- | --- |
| `--enable-use-openmp` | `OPENMP_MODE` | CPU multithreading with OpenMP |
| `--enable-use-openacc` | `OPENACC_MODE` | GPU offloading with OpenACC. **Incompatible with `--enable-use-openmp`** (configure stops with an error). Forces `--enable-rng-philox` |
| `--enable-use-theta` | `THETA_MODE` | Adds the imaginary θ term to the action (4D SU(N), N ≥ 2 only: the topological charge must be defined) |
| `--enable-use-multicanonical` | `MULTICANONICAL_MODE` | Adds the multicanonical bias potential in the topological charge |
| `--enable-rng-philox` | `RNG_PHILOX_MODE` | Counter-based Philox4x32-10 generator instead of dSFMT (streams: [algorithms.md](algorithms.md)). Not a `build.sh` switch: `build.sh` gets it only through OpenACC |
| `--enable-meas-replica` | `REPLICA_MEAS_MODE` | In parallel-tempering programs, measure observables on all replicas, not only on the physical one |
| `--enable-debug` | `DEBUG` | Extra sanity checks (assertions, geometry tests) |

Other compile-time macros, not exposed by configure, can be passed through `CFLAGS` (e.g. `CFLAGS="-O3 -DOPT_MULTIHIT"`):

| Macro | Effect |
| --- | --- |
| `OPT_MULTIHIT` | With `ml_obs POLYCORR`, print diagnostics to choose the number of multihit steps instead of the standard measurement |
| `OPT_MULTILEVEL` | With `ml_obs POLYCORR` (and `POLYCORR_LONG`), print diagnostics to choose the number of multilevel updates |

## Automatic checks done by configure

- Required headers: `complex.h`, `limits.h`, `math.h`, `stdio.h`, `stdlib.h`, `time.h`; `omp.h` with OpenMP.
- `openssl/md5.h` and the `crypto` library: if both are found, `HASH_MODE` is defined and an MD5 hash of every saved
  configuration is written in its header and checked when it is read back. Otherwise a warning is printed and the hash
  is not used.
- NVIDIA HPC SDK detection (`nvc`): if detected, configure appends `-Mvect=nofuse` to `CFLAGS` (works around a wrong
  loop fusion of nvc in consecutive inlined matrix functions) and the Makefile uses nvc-compatible warning flags
  (`-c99 -Minform=warn`) instead of the gcc ones (`-std=c99 -Wall -Wextra -Werror -pedantic -Wconversion`).
- With `--enable-use-openacc`, configure checks that the compiler accepts `OPENACC_CFLAGS` and provides `openacc.h`.

Note that with compilers other than nvc the default warning flags include `-Werror`.

## The `build.sh` script

`build.sh` collects the options in its first section:

| Variable | Meaning |
| --- | --- |
| `NCOLORS`, `STDIM`, `NTHREADS`, `NDEVICES`, `NLEVELS`, `LINK_BLOCK` | Passed as `N_c`, `ST_dim`, `Num_threads`, `Num_devices`, `Num_levels`, `Link_block` |
| `ENABLE_THETA`, `ENABLE_MULTICAN`, `ENABLE_MEAS_REPLICA`, `ENABLE_OPENMP`, `ENABLE_OPENACC`, `ENABLE_DEBUG` | 1/0 switches for the enable options above |
| `COMPILE_CONFIG` | Compiler preset: `gcc`, `nvhpc`, `leonardo`, `leonardo_gpu`, `galileo100`, `marconi` |
| `COMPILE_TARGETS` | `make` targets (default `all`) |
| `BUILD_JOBS`, `BUILD_CLEAN` | Parallel `make` jobs; run `make distclean` first |

Compiler presets:

| Preset | Compiler | Flags | OpenACC flags |
| --- | --- | --- | --- |
| `gcc` | gcc | `-O3` | `-fopenacc` |
| `nvhpc` | nvc | `-O3` | `-acc=host -Minfo=accel` (OpenACC on the host CPU, for testing) |
| `leonardo_gpu` | nvc (modules `nvhpc/25.11`, `cuda/12.2`) | `-O3` | `-acc=gpu -gpu=cc80 -Minfo=accel` (A100) |
| `leonardo`, `galileo100`, `marconi` | icc (Intel modules) | `-O3 -axCORE-AVX512 -mtune=<arch> -ip -ipo` | not supported |

The script stops if both OpenMP and OpenACC are enabled, or if OpenACC is requested with a preset that has no OpenACC
flags. It links with `LIBS="-ldl -lz -lc"`.

## Compile-time limits and incompatibilities

| Constraint | Where it is enforced |
| --- | --- |
| OpenMP and OpenACC cannot be combined | `configure`, `build.sh` |
| OpenACC implies Philox RNG | `configure` |
| θ term only with `ST_dim=4` and `N_c ≥ 2` (the topological charge must be defined) | `#error` in [include/macro.h](../include/macro.h) and in `calcstaples_with_topo` ([lib/gauge_conf_upd.c](../lib/gauge_conf_upd.c)); check in `readinput` ([lib/gparam.c](../lib/gparam.c)) |
| Topological observables (including `charge_density_meas`) and multicanonical mode only for (`ST_dim=4`, `N_c ≥ 2`) or (`ST_dim=2`, `N_c=1`) | `readinput` (runtime error at start) |
| `Link_block` a power of 2 from 1 to 256 | `configure`, `#error` in [include/macro.h](../include/macro.h) |
| PTBC programs only for `ST_dim=4`, `N_c ≥ 2` | `main` of `yang_mills_local_pt_agf` and `yang_mills_tuning_pt_mc` (runtime error at start) |
| `yang_mills_tuning_pt_mc` requires `--enable-use-multicanonical` | runtime error at start |
| Multilevel programs refuse `--enable-use-multicanonical` | runtime error at start |
| Multilevel and trace-deformation programs are not built with OpenACC | [Makefile.am](../Makefile.am) |
| `conf_txt_to_bin` works only for `N_c ≥ 3` | its `main` |
| GPUs must be NVIDIA (the device query uses `acc_device_nvidia`) | `init_device_utils` ([lib/device.c](../lib/device.c)) |
